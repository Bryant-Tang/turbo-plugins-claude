## 這件事該寫在哪（由 turbo-plugin 注入）

寫錯地方不會報錯,只會在半年後以「過期的文件把人帶錯路」或「交接之後這件事沒人知道」的形式浮出來。

| 這件事的性質 | 落點 |
|---|---|
| 對**任何時間** checkout 這個 repo 的人都成立 | 本檔 `CLAUDE.md` 或 `docs/` |
| 只有**現在**成立(待辦、環境現況、本機分支關係),但**接手的人需要知道** | agent 記憶,`type: project` |
| agent 自己的工作方式,或只對**這台機器 / 這個人**成立、**不需要交接**的事 | agent 記憶,`type: feedback` / `user` / `reference` |
| git / svn 本身就查得到 | 哪都不要寫 |

**進版控的再分一層**:`CLAUDE.md` 放「**在你還不知道自己需要它的時候就會發作**」的東西——地雷、沉默失敗的陷阱、硬規則;不知道它存在就不會去查,所以必須無條件載入。`docs/` 放「**刻意要做某件事才會需要**」的東西——操作步驟、查表用的參考;這類自然會去查,延後載入沒有風險。

### 第二、三列都落在記憶,分野是「會不會被交接」

記憶**不會跟著 repo 走**——換人、換機器就沒了。所以判準不是「進不進版控」(兩者都不進),而是多問一句:

> **這件事換人接手還需要嗎?**

需要 → 寫成 `type: project`,並在 `MEMORY.md` 留一行索引。不需要 → `feedback` / `user` / `reference`。

交接時跑 **`/tp-export-handover`**,它會把 `project` 那些整理成一份可讀的檔案交出去。**這條路徑必須真的被走過才算數**:記憶沒有匯出過的專案,等於「接手的人需要知道」那一格是空的。

### 不要用一份不進版控的 `TODO.md` 當待辦落點

那個格子——「不進版控、但屬於交接內容」——**沒有任何工具支援**:git 不管它(被 ignore),隔離工作副本只把它帶進去、不搬回來,兩個副本各自加了一條也沒有任何東西能合併。想替它補機制,補出來的每一樣都是在重造 merge(快照=merge base、三態=three-way merge、衝突檔=conflict file)。所以待辦落在記憶,交接靠匯出。

已經有一份**進了版控**的 `TODO.md` 是另一回事:那就是文件,適用上表第一列。

### 被 git 忽略的檔案:三個不變式

隔離工作副本(worktree / 鏡像)對這些檔案**只帶進去,不搬回來**。在副本裡對它們做的任何編輯,副本消失時就跟著沒了,而且**不會有任何警告**。所以放在版控外的檔案必須同時滿足:

1. **不是用來編輯的** — 不要把只存在於那個檔案裡的內容寫進去。
2. **可以重新產生** — 刪掉之後有辦法再生出來(重跑 setup、從範本複製、重新下載)。
3. **可以接受手動編輯** — 使用者手改是預期用法,不會被下一次自動寫入無聲覆蓋。

三條有一條不成立,那份內容就不該待在版控外——它要嘛進版控,要嘛進記憶。
