# 該不該進版控 —— 判準（給 agent 用，不是清單）

> 這份檔案被 `tp-suggest-ignore`、`tp-setup`、`tp-push-to-svn` 三處共用。**只有這一份**，改就改這裡。

## 為什麼是判準不是清單

一份寫死的 pattern 清單（`bin/`、`obj/`、`.vs/`…）永遠只對某個技術棧成立，而且會同時犯兩種錯：
漏掉這個專案真正的產物（清單沒列到的框架、自訂輸出目錄、產生器的輸出），又硬塞不適用的項目
（有些專案真的要把 `packages/` 或某個 `bin/` 進版控）。**你看得到這個專案的實際內容，清單看不到。**

所以:**先看專案是什麼，再判斷每個檔案是什麼**。可以從 `*.csproj` / `*.sln` / `package.json` /
`requirements.txt` / `pom.xml` / `Makefile` / CI 設定推出這個專案的建置產物長什麼樣，也可以直接看檔案內容。

## 兩類 ignore，責任不同

| 類別 | 誰負責 | 說明 |
|---|---|---|
| **plugin 自造的基礎設施** | **setup 寫死**，不由你判斷 | `.turbo-plugin/worktrees/`、`.svn/`、`.claude/**/*.local.*`、`.turbo-plugin/**/*.local.*`。這些是 plugin 自己造出來的東西，形狀固定、且**必須在任何 `git add` 之前**就位（見下方硬規則）。 |
| **專案自己的產物與機密** | **你判斷** | 建置輸出、套件快取、IDE / 編輯器狀態、本機設定、憑證。沒有固定清單。 |

**硬規則:基礎設施那四條不可以被移除。** `.svn/` 一旦不再被忽略，bridge worktree 的 SVN 管理目錄就會被
`git add` 掃進版控、接著推上 SVN；`.turbo-plugin/worktrees/` 不再被忽略，巢狀 worktree 會污染主 worktree 的
`git status`。使用者要求移除這些 pattern 時，**說明後果並拒絕**，不要照做。

## 判準（逐檔問這幾個問題）

**應該 ignore —— 命中任何一條就是候選:**

1. **可以從版控內容重新產生嗎?** 建置輸出、編譯產物、打包結果、程式碼產生器的輸出、轉譯結果。
   判準是「刪掉之後跑一次建置就會回來」。
2. **是套件管理器可以還原的相依嗎?** 下載回來的套件、`node_modules` 之類的快取。
   判準是「有 lock / manifest 就能還原」——**manifest 與 lock 本身要進版控**。
3. **只對這台機器 / 這個使用者成立嗎?** 絕對路徑、本機 port、個人編輯器偏好、使用者專屬的專案設定檔。
4. **是機密嗎?** 密碼、連線字串、API token、私鑰、憑證。**這一類最嚴重**：一旦推上 SVN 就是永久的，
   之後把檔案刪掉也救不回來（歷史裡還在）。發現這類東西要**主動且明確**地講。
5. **是純粹的雜訊嗎?** log、暫存檔、當機傾印、作業系統產生的目錄檔。

**不應該 ignore —— 命中任何一條就排除:**

1. **別人 clone 下來少了它就跑不起來/建不出來。**
2. **它是設定的來源，不是設定的產物**（範本、`.example` 檔、manifest、lock 檔）。
3. **雖然是產生出來的，但這個專案刻意把它進版控**（有些專案會把產生的程式碼或前端 build 產物一起進去）。
   判斷方式:看它是不是**已經在版控裡而且有人在維護它的變更**——已經被追蹤很久的檔案，預設就是刻意的。
4. **不確定。** 不確定就不要動，或者問使用者。誤判成該 ignore 的代價（別人少一個檔案、build 壞掉）
   比留著不管大得多。

## 講給使用者聽的時候

- 用**白話描述這個檔案是什麼**（「這是建置產生的輸出目錄」「這看起來是資料庫連線字串」），
  不要只丟 pattern 或內部術語。
- 機密要單獨講、講在最前面，不要混在一串產物裡帶過。
- 你在猜的時候要說你在猜。
