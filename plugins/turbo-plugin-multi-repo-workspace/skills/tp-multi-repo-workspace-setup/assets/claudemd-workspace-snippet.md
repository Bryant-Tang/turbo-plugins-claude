> **這對 `turbo-plugin:begin` / `end` 標記之間的內容由 turbo-plugin 產生,重跑 setup 時會被整段取代。**
> 不要往裡面加東西——加的當下不會有任何錯誤或警告,直到某次更新把它無聲刪掉。你自己的規範寫在標記**外面**。

## 這個資料夾是多專案工作區

這個資料夾**本身不是** git repo。它底下的每一個子資料夾各自是一個**獨立的 git repo**——自己的歷史、
自己的分支、自己的 `CLAUDE.md`。

### 動任何一個子專案之前，先讀它自己的 `CLAUDE.md`

子資料夾的 `CLAUDE.md` **會**被自動發現，但是**延遲載入**——只有在你實際讀取那個資料夾底下的檔案之後
才會進 context。兩個後果：

- **還沒讀檔就開始規劃**時，你手上沒有那個專案的規範。要動某個子專案，**先讀它的 `CLAUDE.md`** 再規劃。
- **`/compact` 之後子資料夾的 `CLAUDE.md` 不會自動回來**（這個根目錄的會）。壓縮後若要繼續動某個子專案，
  **重新讀一次它的 `CLAUDE.md`**。

### 每個子專案是獨立的 repo，不要跨專案一起 commit

- **會改動東西的 git 指令，必須把 repo 寫進指令本身**（`git -C <子專案路徑> add / commit / ...`）。
  只是查看狀態的話先 `cd` 過去也可以，但**不要在同一串指令裡先 `cd` 再做會改動的事**。
  理由：那等於讓「你剛好站在哪」決定「你動到誰」，而站錯的那個資料夾本身完全合法，不會有任何東西提醒你。
- **`git -C <repo>` 指定了「動哪個 repo」，但沒有指定「動哪個分支」。** 各專案停在哪個分支是**各自獨立**
  的——有的在 `main`，有的可能還停在上次沒切回去的功能分支或測試整合分支。**跨專案批次提交之前，先確認
  每個 repo 站在哪個分支**：

  ```bash
  for d in */; do if [ -d "$d/.git" ]; then printf '%-30s %s\n' "$d" "$(git -C "$d" branch --show-current)"; fi; done
  ```

  理由跟上一條一模一樣，只是換一個維度：停在非預設分支的那個 repo 本身完全合法，`git status` 乾淨，
  commit 也會成功，沒有任何東西提醒你。而如果那條分支不會併回主線，那顆 commit 就等於沒進去，事後得
  切過去 cherry-pick 才救得回來。
- **一次 commit 只包含一個子專案的變更。** 跨專案的一批改動 = 每個專案各自一顆 commit。
- **這個工作區資料夾不要 `git init`。** 在這裡建 repo 會把所有子專案包進同一個 repo，而且事後沒有東西能還原。

### turbo-plugin 的指令要指名專案

turbo-plugin 的指令預設從「當前目錄」往上找 repo，而這個資料夾不是 repo，所以在這裡直接跑會失敗
（`not inside a git repository`）。呼叫時明確指定專案：bash 用 `--repo-root <子專案路徑>`、PowerShell 用
`-RepoRoot <子專案路徑>`。判準見 `turbo-plugin-git-svn` 的 `assets/repo-target.md`。

同一件事在這裡也成立：`--repo-root` / `-RepoRoot` 只指定「動哪個專案」，指令仍然是對那個專案**當前
checkout 的分支**動作。專案指名對了不代表分支就是對的，兩個都要確認。

### 這裡刻意不列出有哪些子專案

子專案清單、各專案的資料庫 / SVN 路徑 / 專屬規範**都不寫在這一段裡**。理由：寫了之後，新增專案或改動其中
任何一項時很容易忘記回來更新，而**過期的清單比沒有清單更糟**——它會讓你依據錯的資訊行動。

要知道有哪些專案，就看這個資料夾底下有哪些子資料夾（有 `.git` 的就是）；要知道某個專案的規範、資料庫或
SVN 設定，就讀它自己的 `CLAUDE.md` 與 `.turbo-plugin/`。

### 要隔離工作副本時，直接在這個根目錄開就好

這個資料夾不是 repo，但 `turbo-plugin-multi-repo-workspace` 提供了 `WorktreeCreate` hook，所以在這裡開
隔離工作副本**是可以的**——你會被放到 `<工作區根>/.worktrees/<名稱>/`，那底下每個子專案各是一份真正的
worktree。**不要為了開隔離而先 `cd` 進某個子專案**：那樣 session 就被釘在那一個專案上，其他專案動不了，
而這個工作區的意義就是一次管全部。

站進鏡像目錄之後，操作方式完全不變：仍然是 `git -C <子專案>`，只是那個子專案現在指向隔離副本而不是主
checkout。若某個子專案在鏡像裡不存在，那是**大聲的**失敗（找不到檔案），不要改去動主 checkout。

### 「這件事該寫在哪」的判準在各專案自己的 `CLAUDE.md`

`tp-setup` 會把那張四格判準表注入每個專案的 `CLAUDE.md`，並在專案根建一份 `TODO.md`（不進版控，但
**屬於交接內容**）當「只有現在成立、但接手的人需要知道」那一格的落點。**屬於單一專案的現況與待辦寫進
那個專案的 `TODO.md`，不要集中寫在這個工作區根**——集中寫的那份不會跟著專案交接出去，而且會愈長愈像
一份沒人維護的清單。
