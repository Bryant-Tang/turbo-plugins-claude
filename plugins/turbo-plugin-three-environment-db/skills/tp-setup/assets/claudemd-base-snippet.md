## 專案慣例（由 turbo-plugin 注入）

**不得提交僅限本機才有的東西**:機器路徑、內部 hostname / URL、僅本機 / 單次情境識別碼(需求 / 計畫 / 任務代號、單一 session 項目編號),一律不得寫進版控(文件需舉例時改用 placeholder token)。

### 這件事該寫在哪

寫錯地方不會報錯,只會在半年後以「過期的文件把人帶錯路」或「交接之後這件事沒人知道」的形式浮出來。

| 這件事的性質 | 落點 |
|---|---|
| 對**任何時間** checkout 這個 repo 的人都成立 | 本檔 `CLAUDE.md` 或 `docs/` |
| 只有**現在**成立(待辦、環境現況、本機分支關係),但**接手的人需要知道** | 專案根 `TODO.md`(不進版控,但**屬於交接內容**) |
| 只對**這台機器 / 這個人**成立,**而且不需要交接** | agent 記憶 |
| git / svn 本身就查得到 | 哪都不要寫 |

**進版控的再分一層**:`CLAUDE.md` 放「**在你還不知道自己需要它的時候就會發作**」的東西——地雷、沉默失敗的陷阱、硬規則;不知道它存在就不會去查,所以必須無條件載入。`docs/` 放「**刻意要做某件事才會需要**」的東西——操作步驟、查表用的參考;這類自然會去查,延後載入沒有風險。

**第三列的判準是「會不會交接」,不是「進不進版控」。** agent 記憶不會交接——換人、換機器就沒了。所以**凡是專案需要遵守或知道的事,即使只有現在成立、即使不該進版控,也不能只留在記憶裡**,它必須落在會被交接的地方(也就是 `TODO.md`)。記憶只收兩類:agent 自己的工作方式,以及只對這台機器成立、下一個人根本不需要的東西。這兩者都「不進版控」,光看進不進版控分不出來,要多問一句**「這件事換人接手還需要嗎?」**
